# Runbook — M5.7 production cutover to the project model (v1.1)

**Why a runbook:** the cutover mass-deletes ThingsBoard tenants and drops the portal database on the
**production** host. The safety classifier blocks Claude from running destructive prod commands via
automation, so run these yourself from a workstation that has the deploy key (`~/.ssh/chertiot_deploy`).
Build phase, so this is a clean reset (owner-approved: "rebuild fresh"). **Prod is not yet live.**

**Rollback:** git tag `v1.7.0` + DigitalOcean snapshot `chertiotserver2-1789678954150`. Nothing here
is reversible in-place — rely on the snapshot if needed.

**Current prod state (already done, safe):** `main` is checked out at `b4b4ea8`; the new portal image
`chertiot/portal:dev` is built but **not deployed** — the running portal is still the old container.
Do the steps **in order**; do not `compose up portal` before the DB reset (step 4) or it will migrate
the old database instead of a fresh one.

```bash
HOST=134.122.31.32
SSH="ssh -i $HOME/.ssh/chertiot_deploy -o IdentitiesOnly=yes chertiot@$HOST"

# 1) Wipe old per-user TB tenants (fresh start). Uses the running portal's sysadmin creds.
$SSH 'cat > /tmp/wipe.py <<PY
import os, httpx
TB = os.environ["TB_ADMIN_URL"].rstrip("/") + "/api"
s = httpx.post(f"{TB}/auth/login", json={"username": os.environ["TB_SYSADMIN_EMAIL"], "password": os.environ["TB_SYSADMIN_PASSWORD"]}, timeout=20).json()["token"]
h = {"X-Authorization": f"Bearer {s}"}
with httpx.Client(timeout=30) as c:
    ts = c.get(f"{TB}/tenants?pageSize=1000&page=0", headers=h).json().get("data", [])
    print("deleting", len(ts), "tenants")
    for t in ts: c.delete(f"{TB}/tenant/{t[\"id\"][\"id\"]}", headers=h)
print("done")
PY'
$SSH 'P=$(cd /srv/chertiot && docker compose -f docker-compose.yml ps -q portal); docker cp /tmp/wipe.py $P:/tmp/wipe.py && docker exec $P /app/.venv/bin/python /tmp/wipe.py'

# 2) Stop the portal (release DB connections)
$SSH 'cd /srv/chertiot && docker compose -f docker-compose.yml stop portal'

# 3) Drop + recreate the portal database (fresh schema on next start)
$SSH 'cd /srv/chertiot && docker compose -f docker-compose.yml exec -T postgres psql -U chertiot -d postgres -c "DROP DATABASE IF EXISTS portal;" -c "CREATE DATABASE portal OWNER chertiot;"'

# 4) Start the new portal (docker-entrypoint runs alembic upgrade head → migration 0005)
$SSH 'cd /srv/chertiot && docker compose -f docker-compose.yml --profile core --profile flows up -d portal'

# 5) Verify: healthy + schema at 0005
$SSH 'cd /srv/chertiot && docker compose -f docker-compose.yml ps --format "{{.Service}} {{.Status}}" portal'
$SSH 'cd /srv/chertiot && docker compose -f docker-compose.yml exec -T postgres psql -U chertiot -d portal -tAc "select version_num from alembic_version"'   # expect 0005
curl -s -o /dev/null -w "%{http_code}\n" https://chertiot.com/healthz   # expect 200
```

## 6) Reseed a demo project (optional, recommended)
Creates a demo owner + one provisioned project so the platform isn't empty. Run on prod:

```bash
$SSH 'cat > /tmp/seed.py <<PY
import uuid
from sqlalchemy.orm import Session
from app.db import get_engine
from app.models import PortalUser
from app import project as P
db = Session(get_engine())
u = PortalUser(email="demo-owner@chertiot.com", kc_user_id=uuid.uuid4().hex)
db.add(u); db.commit()
pr = P.create_project(db, u, "Greenhouse monitor", "Demo project — temperature & humidity")
print("project", pr.slug, pr.provisioning_state, pr.tb_tenant_id)
PY'
$SSH 'P=$(cd /srv/chertiot && docker compose -f docker-compose.yml ps -q portal); docker cp /tmp/seed.py $P:/tmp/seed.py && docker exec -w /app -e PYTHONPATH=/app $P /app/.venv/bin/python /tmp/seed.py'
```

Then create a matching **verified Keycloak login** so someone can sign in as that demo owner (same as
staging). Ask Claude to run the `mk_login` helper, or in the portal container:
`KeycloakAdmin().create_user(...)` then PUT `emailVerified=true, requiredActions=[]`.

## Notes
- The `demo-owner@chertiot.com` **portal** row (step 6) is separate from the **Keycloak** login; a
  person signs in via Keycloak, and the portal adopts/links the row by email on first login.
- If you'd rather Claude run steps 1–6, grant a Bash permission rule for the prod host (or run in a
  session where the destructive-command classifier is relaxed) and tell Claude to proceed.
- After cutover, prod runs the v1.1 project model exactly like staging (verified there end-to-end).
